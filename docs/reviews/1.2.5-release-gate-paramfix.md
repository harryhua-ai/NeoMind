## 附：gate 后参数链路全面审计（前后端 + 内置引擎）

发布前对推理参数全链路做了逐路径核查（前端 UI → REST → 实例存储 → 会话绑定 →
请求构造 → llama-server）。发现并修复三处遗漏（均在 0a6ccfe1 之后的补丁提交中）：

1. **PATCH /llm-backends/{id} 丢弃 top_k**：UpdateBackendRequest 声明了字段、前端
   编辑表单也在发送，但 handler 不应用——UI 改 top_k 无效。已补应用。
2. **编辑激活后端不重绑会话**：更新只 upsert 实例，会话管理器持有的请求设置快照
   不刷新，用户编辑需重启或手动重新激活才生效。现更新后若为当前激活聊天后端，
   立即 set_llm_backend_instance 重绑（既有+未来会话）；绑定其他后端的会话保持
   自身设置（隔离不变）。
3. **内置引擎冷启动实例不带官方采样**：安装/切换路径（handlers::spawn_builtin_server）
   已把目录官方参数写进实例字段，但 bootstrap 重建路径不写——新建设实例落存储默认
   0.6/0.85/20，请求级参数会覆盖 spawn 的 --temp/--top-p/--top-k 官方值。已对齐补齐
   （min_p/repeat_penalty 无请求字段，继续由启动 flag 生效，本来就闭环）。

**gate 有效性**：三处修复都不触及 gate 所测的请求构造路径（get_effective_params /
llamacpp 序列化 / 会话创建绑定）；gate 的实例由 harness 显式建参（1.0/0.95/20），
且行为可用确定性断言（单测/HTTP 捕获）验证，无需重跑模型全量。

其余路径核查结论（无需改动）：Ollama 请求本就序列化 top_k；OpenAI 兼容/云端协议
无 top_k 字段（按协议正确丢弃）；定时 agent 的结构化推理固定确定性参数
（temp 0.1 + 关思考 + JSON 约束，代码内注明为有意设计）；会话级显式温度覆盖经
CreateSessionOptions 保留优先级；全局默认温度（偏好设置 AgentDefaults）作为无绑定
时的回退层正常工作。
